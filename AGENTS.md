# AGENTS.md

Rules for any coding agent working in PoleLine.

## Product

A mobile web game. The player draws a racing line around a real F1 circuit with a finger, picks a tyre, and the car runs that line in real time. Times go on a per-circuit global leaderboard. Keep the core loop tight: pick circuit, pick tyre, draw, watch, read the result, go again.

The same game ships in two editions from one codebase (`src/app/edition.ts`):

- **Web** (`VITE_EDITION` unset): real circuits, the world leaderboard, lap alerts, home screen install and update checks. This is https://pole-line.vercel.app.
- **Toybox** (`VITE_EDITION=toybox`): the paid mobile app for Android and iOS, published by Toyboxes (Randroid LLC) as `app.toyboxes.poleline`. Twenty made-up circuits and nine made-up teams, nothing real, nothing on a server: every lap, best and setting stays on the device, and the Android app requests no network permission. The game code is the web game; Capacitor wraps the Vite build in native shells under `mobile/`. See `mobile/README.md`.

## Rules

1. **No em dashes or en dashes.** Not in code, comments, copy, commits or PRs. Use a period, comma, colon or parentheses.
2. **Commit messages and PR descriptions read as written by a human.** No AI attribution, no generated-by footers.
3. **`src/sim` must stay deterministic.** It runs in the browser and in `api/leaderboard.ts`, and the same quantised line plus tyre must give the same lap time on every JS engine. On the timing path use only `+ - * /`, `Math.sqrt`, comparisons and `Math.floor/round`. No `Math.sin/cos/exp/pow/atan2/hypot`, no randomness, no DOM. Relative imports inside `src/sim` and `src/data` keep their `.js` extension (the Vercel function runs as ESM).
4. **The car is a 2026-regulation car** (active aero straight/corner modes, MGU-K taper, battery and clipping). Keep `src/sim/car.ts` and the README's simulation section in step.
5. **Bump `SIM_VERSION` (`src/sim/version.ts`) whenever a change can alter any lap time.** Leaderboard keys and saved bests are versioned by it.
6. **Track data is generated.** Edit `scripts/track-config.ts`, then run `npm run tracks:build`. After any physics change run `npm run tracks:calibrate` and then `npm run tracks:build` again so each circuit's ideal lap stays just under real pole pace. The tutorial circuit (Rookie Ring, `tutorial: true`) is made up: its outline comes from `scripts/rookie-ring.ts`, it is calibrated on mediums, it is not a championship round, and `src/data/tutorial.ts` (its pre-drawn line) is regenerated by the build; the server rejects tutorial laps that do not start with that line.
7. **Copy is sentence case and plain.** Purple, green and yellow keep their F1 timing meanings.
8. Never commit `.env*` files or print secrets.
9. **The Toybox edition names nothing real.** No real circuit, place, series, team or driver in its circuits, teams or copy. Branch copy on `REAL_CIRCUITS` from `src/app/edition.ts`, and gate server features on `LOCAL_ONLY`: a class method cannot be tree-shaken, so web-only code that must stay out of the mobile bundle lives in its own module behind an `if (LOCAL_ONLY)` branch (see `src/screens/world-board.ts`). `npm run toybox:check` scans the built bundle and fails on a real name or a known server route marker.
10. **Toybox circuits are generated too.** Edit the corner lists in `scripts/toybox/circuits.ts`, then run `npm run toybox:tracks`, `npm run toybox:calibrate` and `npm run toybox:tracks` again. Pole pace on a made-up circuit comes from its `grip` (the ideal line beats pole by the same margin as on the real circuits), so a changed layout or grip changes pole. The tutorial circuit is shared by both editions and keeps the web calibration.
11. **Mobile builds bump both version numbers together**: `versionCode` in `mobile/android/app/build.gradle` and `CURRENT_PROJECT_VERSION` in the Xcode project, one step per store upload.

## Commands

```bash
npm run dev          # Vite on :5199 (API routes need `vercel dev`)
npm run typecheck
npm test             # sim + API tests
npm run build
npx tsx scripts/playtest.ts spielberg ideal /tmp/play   # scripted phone playtest with screenshots (dev server running)
npx tsx scripts/calibrate.ts --report                  # lap times, tyre gaps, sensitivity per circuit
npx tsx scripts/tidytest.ts                            # tidy strokes (medium) against freehand (hard) on hand-like laps, headless
npx tsx scripts/easytest.ts                            # drawing modes in the browser: settings and default, a corrected stroke, a curve's handles (dev server running)
npx tsx scripts/curvetest.ts spielberg /tmp/curves     # tap and bend: a whole lap of taps and bends, then the race (dev server running)
npx tsx scripts/closetest.ts                           # closing the loop: a last dot or lift on the start point finishes the lap in every mode, never 99% (dev server running)
npx tsx scripts/tutorialtest.ts                        # the guided first lap: difficulty on the welcome card, the pause menu, copy that follows the mode (dev server running)
DRAW=smooth npx tsx scripts/playtest.ts spielberg wobbly /tmp/play   # the scripted playtest with every stroke corrected (playtest draws freehand unless DRAW is set)

npm run toybox:tracks        # solve the made-up circuits (contact sheet: add --sheet /tmp/sheet.png to make-circuits.ts) and build src/data/toybox
npm run toybox:calibrate     # pole pace, sectors and clipping speed per made-up circuit
npm run build:toybox         # the mobile bundle in dist-toybox
npm run toybox:check         # no real names, no server routes in that bundle
npm run mobile:sync          # build and copy into mobile/android and mobile/ios
npm run dev:toybox           # Toybox edition in a browser on :5299 (the plain dev server is the web edition)
EDITION=toybox npx tsx scripts/playtest.ts harbour-loop ideal /tmp/play http://localhost:5299/   # scripted playtest of it
CDP=http://localhost:9223 EDITION=toybox npx tsx scripts/playtest.ts ember-gorge good /tmp/play  # the same lap inside the Android app (see mobile/README.md)
```
